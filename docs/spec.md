# Tape v1: personal menu bar time tracking

**Status:** approved

**Scope:** Native Swift app for one person's Mac. This spec records the approved design interview, including the native macOS design requirement. Ticket decomposition is reviewed separately before publication.

## Problem Statement

I want to record what I am working on without managing a full desktop app. I need to see my time as a continuous strip, add work I forgot to track, and reuse the same task across multiple days. Locking or sleeping my Mac should exclude that absence without making me manually restart a timer every time I return.

## Solution

Tape launches in the macOS menu bar with no Dock icon. An explicitly opened main window provides statistics and Settings; the Dock icon appears while that window is open or minimized. Its popover shows a horizontal timeline and compact tracking controls. Time moves beneath a centered now marker when following the present. Scrolling browses history and the future; pinching adjusts the scale. Drawing on empty timeline space records time, and drawing up to now starts ongoing tracking.

Tasks are reusable names with colors. Each task can have many time entries, but only one task runs at a time and entries never overlap. Lock or sleep stops tracking. A usable return presents a configurable countdown anchored to the menu bar; unless rejected, it resumes the previous task and includes the countdown interval. Everything is stored locally.

The app should look and behave like a native macOS 26 utility, using system controls, typography, and Liquid Glass materials. Native behavior and accessibility are part of acceptance, including the custom timeline.

## User Stories

1. As the user, I want to launch Tape as a menu bar app without a Dock icon, so that it stays available without occupying my workspace.
2. As the user, I want the menu bar icon to indicate whether tracking is running, so that I can check its state at a glance.
3. As the user, I want clicking the icon to open a popover and clicking outside to dismiss it, so that it behaves like a familiar Mac utility.
4. As the user, I want tracking to continue while the popover is closed, so that I can work in other apps.
5. As the user, I want to type a task name and see matching existing tasks, so that I can create or reuse a task in one place.
6. As the user, I want tasks to have reusable names and colors, so that work on the same activity is recognizable across days and weeks.
7. As the user, I want a new task to receive a random, legible color, so that creating it requires only a name.
8. As the user, I want to recolor a task across all its entries, so that I can keep my records consistent.
9. As the user, I want duplicate task names to be prevented regardless of capitalization or surrounding spaces, so that I do not accidentally split one activity into multiple tasks.
10. As the user, I want to start, stop, and switch tasks, so that I can track what I am doing as it changes.
11. As the user, I want to see the running task and its growing timeline entry, so that I know what Tape is recording.
12. As the user, I want to view recorded entries on a continuous horizontal timeline, so that I can understand where my time went.
13. As the user, I want the timeline to follow the present beneath a centered now marker, so that the display stays current.
14. As the user, I want to scroll backward and forward without the view snapping back, so that I can browse time freely.
15. As the user, I want two-finger double-tap and reopening the popover to return to the present, so that I can quickly regain my current context.
16. As the user, I want a configurable default view, initially eight hours, and temporary pinch-to-zoom, so that I can choose how much time I see without zoom buttons.
17. As the user, I want to draw an interval on empty timeline space and then name or select its task, so that I can record work retrospectively.
18. As the user, I want clicking away from a named creation draft to save it, with Escape and Cancel available to discard it, so that leaving the picker does not lose my input.
19. As the user, I want drawing up to or beyond now to start tracking from the selected start time, so that recording recent work can flow directly into ongoing work.
20. As the user, I want overlap attempts explained and rejected without changing existing entries, so that my records remain consistent.
21. As the user, I want to click an entry to change its task or timestamps, so that I can correct mistakes.
22. As the user, I want to resize completed and running entries by dragging their edges with minute snapping, so that common corrections are quick.
23. As the user, I want live tracking to preserve actual timestamps, so that minute snapping does not distort recorded durations.
24. As the user, I want to edit a running entry's task or start without stopping it, so that corrections need not interrupt tracking.
25. As the user, I want deletion to require confirmation and deletion of a running entry to stop tracking, so that accidental actions do not silently remove my work.
26. As the user, I want screen lock and system sleep to stop tracking immediately, so that my absence is not counted as work.
27. As the user, I want ordinary inactivity and display dimming or display-off alone to leave tracking running, so that reading and thinking still count.
28. As the user, I want returning from lock or sleep to show an automatic-continuation countdown, defaulting to nine seconds, without stealing focus, so that I can resume work without interacting with Tape.
29. As the user, I want Reject to cancel continuation and exclude the countdown interval, so that breaks do not become recorded work.
30. As the user, I want the continuation notice to remain visible while I use other apps, and opening Tape to accept it immediately without showing a countdown inside the main window.
31. As the user, I want an uninterrupted countdown to resume the previous task from the time I returned, so that the countdown interval is included.
32. As the user, I want another lock or sleep during the countdown to cancel it and offer a fresh countdown next time, so that repeated interruptions are handled predictably.
33. As the user, I want explicit tracking or entry-editing actions to cancel pending continuation, so that an old task cannot restart over my action.
34. As the user, I want quitting to stop tracking and relaunching to start idle, so that Tape does not count time while it is not running.
35. As the user, I want unexpected-exit recovery to preserve only the last saved tracking point, so that downtime is not silently counted as work.
36. As the user, I want all tasks, entries, and preferences stored on this Mac, so that the app works without an account or network connection.
37. As the user, I want an optional launch-at-login setting that starts off, so that I control whether Tape starts with my session.
38. As the user, I want native controls, Liquid Glass, keyboard behavior, and accessible labels, so that Tape feels at home on macOS.
39. As the user, I want light/dark appearance and contrast, transparency, and motion preferences respected, so that the interface remains comfortable and legible.
40. As the user, I want a locally runnable app with reproducible build instructions, so that I can use and maintain it on my own Mac.

## Implementation Decisions

### App and UI boundaries

- Build in Swift for macOS 26.0 or later, using SwiftUI and AppKit where needed for menu bar integration, focus behavior, and system lifecycle events. The verified development machine runs macOS 26.6.2 on Apple Silicon, with Xcode 26.5 and Swift 6.3.2.
- Use a native status item/popover integration that supports both deliberate user interaction and automatic, non-focus-stealing continuation presentation. Verify these behaviors with a runnable app early; do not assume an ordinary interactive popover automatically meets the focus requirement.
- Keep the menu bar icon compact; task names belong inside the popover; omit the elapsed-time display for now. Left-click opens the timeline with Start/task selection, Stop and task switching. Return to Now uses two-finger double-tap, without a dedicated button. Secondary click (including trackpad secondary click and Control-click) opens a native actions menu containing Open Tape and Quit Tape. A plain gear icon at the right of the popover controls opens the main window, with the tooltip and accessible label “Open Tape.” The popover has no three-dot menu or Quit action.
- Keep tracking operations separate from view rendering and system-event delivery. Route mutations through a single application-level boundary so overlap validation, persistence, and cancellation rules apply consistently to every interaction.
- The default popover shows the current state and timeline, with task selection hidden behind Start task or Switch task. Show these header actions as plain icons: play for Start task, opposing arrows for Switch task, and a square for Stop. Keep tooltips and accessible labels, with no visible text or button backgrounds. Revealing the inline picker focuses its search field. Successful task selection or Escape collapses the picker; Escape with no picker open dismisses the popover. Reopening starts with the picker hidden. Keep the layout compact without titles or subtitles. Keep the picker and entry editor below the timeline without dividers. Task suggestions show only their color dot and name, without trailing action icons. Always show the date or visible date range above the timeline, including while following now.
- Separate timeline coordinate/gesture calculations from tracking timestamps. Rendering cadence must not determine elapsed time or create persistent writes for every animation frame. Avoid continuous timeline rendering while its popover is closed.

### Main window and Settings

The [main-window task](../tasks/20261020-194050/TASK.md) adds the following behavior:

- Launch with the main window closed, including after quitting with it open. Open it only through an explicit user action. The popover button, status menu's Statistics…, General Settings… and About Tape items, and application menu's Settings… command with Command-comma open the same window.
- Use a native, resizable window with Tape as its accessibility/window-menu title, initially 900 × 600. Follow System Settings visually: hide the app title, extend the sidebar behind the standard close/minimize/zoom controls, and show native grouped back and forward buttons beside the current page heading in the detail toolbar above a native grouped form. Back and Forward navigate page history and disable at its boundaries. Selecting a new page after going back clears forward history. The green button zooms rather than entering full screen; this also lets AeroSpace float the window through its native dialog heuristic. Remember its size and position. Its always-visible sidebar starts around 200 points wide and contains Statistics, General, and About, with General initially selected when the window first opens.
- Show the Dock icon and app-switcher entry while the window is open, including minimized. Repeated opening restores and focuses the existing window. Closing it returns to menu-bar-only operation without stopping tracking or quitting.
- Opening the window saves a named creation draft before dismissing the popover. Unnamed drafts and unconfirmed overwrite drafts are discarded; a failed save retains the draft and blocks navigation. It accepts pending continuation just like opening the timeline.
- The menu bar secondary-click menu lists Statistics…, General Settings… and About Tape in sidebar order, followed by a separator and Quit Tape. Each section item selects its destination directly, reusing and focusing the main window whether visible, minimized, or closed. Right-click, trackpad secondary click, and Control-click use the same menu.
- General contains a native Default zoom slider with seven equally spaced stops at 1, 2, 4, 8, 12, 16, and 24 hours, initially 8. Place the title and description beside the slider, with labels only below 1, 8, and 24 hours. Keep the row side by side in narrow windows, wrapping the description and shrinking the slider. Map older values to the nearest stop, choosing the lower value on a tie. Save changes automatically, report failures, and apply the saved choice on the next timeline opening or reset. Keep pinch zoom's wider internal range. Older saved pinch zoom does not become the configured default.
- Statistics starts on the current calendar week with a tag breakdown. Provide Day, Week, Month, previous/next period (no future periods), and a current-period button. Display total time, task-colored day sessions, and daily bars for weeks/months stacked by the selected Tasks / Tags grouping. Split each session equally among its tags for the stack, preserving actual elapsed time; breakdown tag totals remain overlapping. A selected tag gets its full matching duration, and unrelated time stays gray. Hover shows the segment shares. Selecting a daily bar opens that day; selecting a session filters by its task. Searchable task/tag rows sort by duration and select a filter, with durations only in the Time column. Keep sibling rows visible in the selected grouping; switching grouping shows rows within the selection. Each tag uses the current color of the task with its earliest recorded entry across all history; use it for row dots and filtered chart highlights. Untagged stays neutral. Show a removable active filter and total context, without instructional captions or chart subtitles. Use a native table with alternating row backgrounds and selection. Keep the chart and table controls fixed while rows scroll independently; align the grouping picker with the table and adapt the chart height in short windows.
- Statistics is derived without persistence. Clip entries to the period and now, split at local calendar midnights, and account for 23/25-hour days. Count overlapping tags separately without duplicating overall tracked time. Use current task metadata, include live entries, and refresh elapsed time every ten seconds. Preserve explored statistics state across page switches and window reopening. Custom ranges, exports and editing from statistics are outside this version.
- About uses the same grouped form style and shows the app icon, name, tagline, bundled version, license name, a Source Code link with a code icon, and local-data information. Provide Show Data in Finder when the tracking file exists. Navigation preserves tracking, saved preferences, window geometry, and sidebar width; leaving General commits a pending countdown edit.
- General also contains a native Time format menu with System, 12-hour, and 24-hour choices, defaulting to System. Save automatically and apply immediately to timeline time labels, entry tooltips, and time-bearing accessibility descriptions. Preserve the current calendar, time zone, midnight date markers, stored timestamps, and tracking. Older or unknown saved formats use System; failed saves retain the previous choice.
- General’s Tracking section contains a native Task order menu: Recently used (default), Alphabetical, and Most used. Apply the saved choice to task suggestions for both creation and editing, including case-insensitive substring searches. Recency means the latest entry start time; usage means entry count, including a running entry. Break ties by natural alphabetical order and put tasks without entries last for recency and usage. Derive rankings from current entries so edits, reassignments, and deletions apply immediately. Older stores and unknown saved choices default to Recently used. Save automatically without changing tracking records; failed saves retain the previous choice.

### Records and invariants

- A task has a stable identifier, display name, and color. Remove tasks with no remaining entries as part of the same atomic save; tasks with recorded time remain reusable. Trim names, reject empty names, and compare names without case sensitivity when checking uniqueness. Recoloring retains identity and applies to all linked entries. Task renaming is not supported.
- Use a nine-color palette, grouped by shade in the picker: red, orange, brown, yellow, green, teal, blue, purple, and pink. Pink uses a rosier custom shade (#F062B3). Randomly choose among colors unused by tasks with entries; when all colors are used, choose from the full palette. When loading removed shades, map mint and cyan to teal and indigo to blue; preserve task identity and entries. Keep other assigned colors unchanged and check palette legibility during appearance verification. Allow later color changes while keeping labels readable. Task color is not the only indication of identity.
- A time entry has a stable identifier, task reference, start instant, and either a fixed end instant or running state. Only one entry can be running. The running entry continues accumulating time without a numeric elapsed-time display.
- Use absolute instants for storage and duration calculation, with local dates/times for presentation. Preserve durations across midnight and daylight-saving transitions; timeline resizing operates on absolute instants so repeated local hours do not silently change duration.
- Completed entries have positive duration, end no later than now, and do not overlap. Touching endpoints are allowed. Treat intervals as start-inclusive and end-exclusive so switching tasks at one instant produces adjacent entries.
- Starting a different task ends the previous entry and starts the new entry at the same instant as one operation. Starting the already-running task is a no-op. These are implementation defaults that preserve the single-running-task rule.
- Apply validation again when committing an edit or completing task selection, because time and tracking state can change while a control is open. Rejected operations preserve existing entries and give a readable explanation.

### Timeline and entry creation

- Show the configured default zoom, initially eight hours, with now centered whenever the popover opens. Maintain following and browsing states. Scrolling enters browsing; two-finger double-tap at the configured default scale and reopening the popover return to following. Pinch zoom lasts only until the popover closes or zoom is reset.
- The now marker denotes actual current time only. It can move offscreen while browsing; a central marker must not relabel a historical time as now.
- Support horizontal trackpad scrolling and Shift+mouse-wheel navigation. Click-and-drag on empty space draws an interval; it does not pan. Pinch changes scale without zoom buttons. Keep zoom stable around the interaction location where practical. A two-finger double-tap resets to the configured default scale, preserving the viewed center and following/browsing state. At the default scale, a two-finger double-tap returns to Now. Animate both transitions with 0.3-second ease-in-out movement of the whole viewport. Direct timeline interaction interrupts the animation; respect Reduce Motion with an immediate transition.
- There is no user-selected product minimum or maximum zoom range. Use finite internal bounds to keep labels, selection, and rendering usable; do not turn those bounds into extra controls or claim the previously suggested ranges were approved.
- Present date context and time ticks at a density appropriate to scale, and render only the visible range. Browsing is not restricted to a fixed day or week. Future space contains planned entries, never recorded future time.
- After a valid drag, focus a native text field that both accepts a new task name and filters existing tasks. Enter/select commits. Clicking outside, toggling the menu-bar icon, opening settings, or selecting another timeline entry also commits a named creation draft before leaving it. Start/Switch begins at submission or dismissal; drawn entries retain their selected range. Escape and the Cancel button discard the draft, as do empty, whitespace-only, and tag-only names on dismissal. A failed save keeps the draft and error visible and blocks dismissal or navigation. No task or entry is persisted by merely typing a draft.
- A wholly historical selection creates a completed entry. A selection with a past start ending at Now creates an open-ended running entry and retains that intent while typing. A selection extending beyond Now retains its future endpoint as an automatic stop; if that endpoint has already passed when submitted, it becomes a completed entry.
- A selection entirely in the future creates a planned entry, separate from recorded time. A selection with no duration, including one that snaps to zero, silently cancels without an error or task picker. Normalize reverse-direction drags before validation. Drawing snaps to one minute with up to two hours visible, five minutes with up to eight hours visible, and fifteen minutes at wider scales. The special endpoint now and neighboring entry boundaries retain their actual instants. Resize timestamps snap to whole minutes.
- Constrain an ordinary drawn selection to the empty gap containing its drag origin. The preview and released interval stop at neighboring entries in either direction, including a running entry. Exact neighboring timestamps take precedence over minute snapping at those boundaries. Revalidate on commit and reject conflicts introduced after selection. Ordinary drawing never truncates or replaces existing entries. The Command-drag exception is described below.

### Command-drag overwrite

- [Ticket 09](../tasks/20261020-190554-ticket-09/TASK.md) adds overwrite drawing. Hold Command at the start of a drag to select across existing entries, including starting inside one. Entry edges take priority and resize that entry. Retain overwrite intent through task selection and show a gray striped preview before committing, with explicit Overwrite or Overwrite & Start submission. Keep the picker compact with Cancel beside Overwrite or Overwrite & Start, without an extra overwrite label or selected-time caption. Overwrite drafts still require explicit submission; Escape, Cancel, or leaving the picker discards them.
- Committing replaces the selected time: trim partially covered edges, delete fully covered entries, and split an entry into two surviving fragments if the new interval covers its middle. Keep uncovered timestamps and task assignments unchanged. Delete a task when its final entry disappears; retain tasks referenced by any surviving or replacement entry. Clean up unused task records from earlier versions on load.
- Merge the overwrite result with directly adjoining entries for the selected task, including fragments on either side and running entries. Continue through the connected same-task entries to form one continuous interval. A real gap or a different task stops merging. Do not merge unrelated history or change ordinary drawing's behavior.
- Preserve ordinary drawing's snapping, cancellation, and historical/through-Now semantics. A historical overwrite leaves any uncovered running tail running; an overwrite through Now starts the selected task instead. Apply the entire replacement atomically after revalidation, preserving the single-running-entry and non-overlap invariants. Cancellation or failure changes no records.

### Planned entries

- Store plans separately from actual entries. Plans reference the same reusable tasks and tags; retain tasks used only by plans. Planned, skipped, and missed time never contributes to statistics. Store format 2 adds plans while continuing to read format 1; older builds must reject format 2 rather than silently dropping plans.
- Drawing entirely in the future schedules both endpoints. A drag from the past beyond Now records its past portion, starts tracking, and schedules its end. Ending at Now retains open-ended tracking. A future draft that becomes due while the user is typing still uses a start countdown, without backfilling the typing time.
- Render unrecorded planned time with a dashed task-colored outline and a faint fill. Actual recorded time stays solid. Missed and skipped portions are gray, with status in the tooltip. The same task/tag editor, color control, edge resizing, and deletion apply to plans. Reschedule moves the whole intended interval to a future start without altering recorded time.
- Ordinary drawing and resizing clamp at neighboring plans; Command-drag explicitly replaces overlapping plans. Plans cannot reserve the same instant. Moving a future plan's start into the past starts tracking from the selected start, subject to the recorded-time overlap rules.
- Announce each scheduled start before its boundary using the configured resume-countdown duration and the existing nonactivating popup style. Start now switches immediately and retains the endpoint; Skip preserves the current task and marks the plan skipped. Scheduled starts switch the running task, but an already-running task with the same identity stays continuous. Announce stops with Stop now and Keep tracking; the latter removes that plan's automatic endpoint. A completed plan leaves tracking idle unless the next plan starts at that boundary. Adjacent same-task plans remain one continuous actual entry.
- Hovering, clicking elsewhere, or opening Tape neither pauses nor accepts a scheduled notice. The scheduler uses awake, unlocked, active-console availability rather than keyboard/mouse idle time. Scheduling is independent of Automatic resume and takes priority over a pending continuation.
- Lock and sleep stop actual tracking immediately. Returning within the intended interval offers a fresh countdown and records only from its completion, keeping the original endpoint. Never include a short break in scheduled tracking. If the plan has expired, or its end would arrive before a late start countdown completes, mark it missed. Apply the same rule after relaunch; Tape must be running for scheduling to execute.
- Manual stop, switch, reassignment away from the task, or deletion of its running entry cancels that plan's remaining automation. Quitting preserves the plan for a later launch while stopping actual tracking. A crash recovers only through the saved checkpoint, capped at the planned endpoint. Failed writes preserve the prior records and plan state and may be retried at the original boundary.


### Corrections and deletion

- Clicking an entry opens an inline editor below the timeline, in the same position as the task picker. A 15-point color circle, task search field, and Delete share one row without a divider. Text fields retain the accepted subtle border and transparent fill. Color changes save immediately. Start and end are edited only by dragging edges; there are no timestamp fields. Clicking empty timeline space deselects the entry. Selecting a suggestion loads its name and tags for review; Return reassigns only this entry, creating a task for a new name. Typing alone does not save. There are no Save or Cancel buttons, and no task renaming. Escape or popover dismissal keeps saved changes and discards drafts. Color changes apply to all linked entries. Completed and running entries support resizing either edge. Dragging an end onto Now continues that same entry as running if no neighboring entry blocks the extension. Dragging beyond Now preserves the entry identity and schedules an automatic stop, without storing future time as recorded work. Drawing and resizing snap to Now within twelve points in both the preview and the committed result; releasing there leaves tracking open-ended and removes any active planned stop.
- A running entry can change task or start while remaining running. Dragging its start preserves tracking. Dragging its live end into the past stops it at that selected time; leaving the end at or beyond Now keeps it running.
- Hold Command before or during edge resizing to overwrite neighboring entries. Modifier changes update the preview immediately, including while the pointer is stationary. Releasing Command restores normal neighbor clamping; mouse-up commits the current mode. Keep the original task color and entry identity. Trim or delete covered neighbors, remove orphan tasks, and merge connected same-task time. Extending through Now can replace an existing running task. Save the entire change atomically, with valid recovery state; Escape or a failed save leaves records unchanged.
- All corrections obey overlap and timestamp invariants. Provide a native confirmation for an explicit entry-deletion action. Cancelling confirmation preserves the entry and running state; confirming deletion of a running entry also stops tracking. Command-drag overwrite commits through its preview and task submission, including any fully covered entries it removes. Overwrite resizing commits on mouse-up after previewing the replacement.
- Initiating an explicit start, entry-creation flow, or entry-editing flow cancels pending continuation before a delayed callback can resume the old task. Do not reinstate the countdown if the user later abandons that action. Opening the main popover accepts continuation immediately. Clicking outside the notice keeps it visible and leaves its countdown running. Subsequent editing does not undo that accepted time.

### Lock, sleep, and continuation

- Screen lock or system sleep ends a running entry at the interruption boundary and remembers its task for possible continuation. Lid closure counts when it causes system sleep; an awake Mac with an external display keeps tracking. Ordinary inactivity and display-off alone do not stop tracking.
- Treat locked and sleeping conditions independently. A return is usable only when awake and unlocked. Duplicate notifications, sleep followed by lock, and wake while still locked must not produce duplicate entries or multiple countdowns.
- If a task was interrupted, a usable return starts one pending continuation using the configured duration and immediately presents a non-activating panel anchored below the menu bar without stealing focus. Highlight the menu bar icon while this notice is visible and clear the highlight when it closes. Show the task name, a decreasing countdown, OK to accept immediately, and Reject. An idle app does not invent a task to resume.
- Clicking outside the panel or using other apps keeps it visible and the countdown running. Clicking OK or opening Tape accepts continuation immediately. The main popover never shows a continuation dialog. Other activity leaves the countdown active. On acceptance or countdown completion, reopen the interrupted entry if the gap from its stopped end to usable return is nonnegative and below the configured short-break threshold. Include that short break in tracked time. Only reopen that same entry if it is still the latest entry for the interrupted task, with no intervening entries. Otherwise start a new entry at usable return. Include elapsed countdown time in both cases. Use elapsed time, not animation frames, to decide completion.
- General → Tracking provides Automatic resume, initially on. When off, lock/sleep still stops tracking but return does not offer or commit a continuation. Disabling it cancels any pending offer only after the preference saves successfully. Re-enabling it does not revive an old interruption. Disable the countdown and short-break controls while off, preserving their saved values.
- Short-break threshold is a native menu with Never, 30 seconds, and 1, 2, 5, 10, 15, 30, or 60 minutes, initially 5 minutes. Preserve non-preset values in the menu. Store exact seconds, reading legacy minute values without rewriting on load; prefer the seconds field if both exist. Zero is displayed as Never and always starts a new entry. At exactly the threshold, start a new entry; only shorter breaks are included. Capture the threshold when the offer begins so changing it affects the next offer. Save without changing entries or recovery checkpoints; older records retain five minutes.
- General → Tracking provides a native Resume countdown text field followed by “seconds”, defaulting to 9 seconds. Accept digits only and save on Return or focus loss. Bound the committed value to 1–60 seconds; empty input restores the saved value. Restore the setting on relaunch. Older records default to 9 seconds; out-of-range stored values are bounded to 1–60 without rewriting on load. Changes apply to the next offer, leaving an existing deadline and hover pause intact. Failed saves retain the previous setting and report an error without changing entries or recovery checkpoints.
- Hovering anywhere over the notice pauses the countdown, preserving its exact remaining time. Leaving resumes it; OK and Reject remain available while paused. Keep the original return instant, including hover time when continuation is accepted. A new lock/sleep clears the pause with the pending countdown.
- Reject clears pending continuation without creating an entry. Another interruption cancels the pending countdown without saving it and retains the original entry and task for a fresh offer on the next usable return. Evaluate the short-break gap from the original stopped end to that latest return.
- An explicit tracking/editing action cancels pending continuation. Stop or Quit also prevents its later completion. Serialize return events, user actions, and countdown completion so at most one continuation can commit; recheck validity before committing.
- Implement and manually verify actual lock/unlock and sleep/wake detection on the target Mac. Keep this integration isolated from the tracking operations so event-ordering tests can use simulated signals. Display inactivity is not an acceptable substitute for screen-lock detection.

### Local durability and lifecycle

- Store tasks, entries, preferences, and recovery information in the user's local application data location, outside the source checkout and app bundle. Use a versioned local store with atomic mutation behavior. Selecting the storage library is an implementation choice; no sync framework is required.
- Persist accepted mutations immediately and checkpoint a running entry periodically. Use five seconds as the initial checkpoint interval and verify that recovery does not include time after the last successfully saved checkpoint. Successful checkpoints must remain consistent with task/entry mutations.
- On deliberate quit, end and save the running entry, clear pending continuation, then exit. Normal relaunch starts idle. Launch at login also starts idle.
- After an unexpected exit, close any formerly running entry at its last saved tracking point and leave tracking stopped. Do not substitute relaunch time as its end or start a continuation countdown. Drop a recovered zero-duration provisional record if needed to preserve valid intervals.
- A pending continuation is not recorded work until accepted by OK, opening Tape, or countdown completion. An unexpected exit during the countdown must not commit it later.
- Surface storage failures without falsely reporting successful saves; preserve the previous valid stored data. Reopening the store must retain task identity, entry links, and the saved zoom preference.
- Provide launch at login in General → Startup using `SMAppService.mainApp`, initially off, and report the actual registration state. Read status when the settings appear and the app becomes active. Register/unregister only on explicit changes; failures report an error and retain the actual OS state. If approval is needed, show an Open System Settings action and do not claim the service is enabled. Login launches remain idle in the menu bar with no main window. Keep the app self-contained with no separately installed background service.

### Native appearance and accessibility

- Prefer standard SwiftUI/AppKit controls, system fonts, semantic colors, standard spacing, and SF Symbols. Use public system materials and let standard popovers and controls adopt Liquid Glass.
- Apply custom glass sparingly to controls. Keep timeline content and task blocks legible without stacking glass effects on each entry. Where a custom text-heavy glass treatment is necessary, prefer the regular variant.
- Follow native focus, hover, selection, keyboard dismissal, and destructive-confirmation conventions. The AirPods comparison describes unobtrusive continuation behavior, not a requirement to reproduce private Apple UI.
- Support light/dark appearance, Reduce Transparency, Reduce Motion, and increased contrast. Reduced animation must not change tracking semantics or stop the clock. Give actionable controls and timeline entries accessible labels and provide keyboard editing through standard fields.
- While tracking, the task-colored dot beside the current task name emits two staggered, expanding and fading pulses. Keep the center steady and the header layout unchanged. With Reduce Motion enabled, show only the static dot. Animate only while the popover is open.
- Time corrections use minute-snapped edge dragging. Do not depend on color alone to identify tasks or the running state.

### Delivery and planning

- Deliver a locally runnable app bundle and source/build instructions for this Mac. No App Store submission, notarized distribution workflow, account system, or hosted component is required.
- Keep the spec in the repository. Track bugs, planned work, and their status in [GitHub Issues](https://github.com/mchernigin/daytape/issues). Do not create or maintain local task files; `tasks/` contains archived records only.

## Testing Decisions

- Test observable tracking operations and resulting records/state through the single application-level mutation boundary. Avoid tests of private methods, view structure, or framework implementation details. There is no existing test suite or prior implementation in this initially empty repository.
- Inject controllable time and system-event signals at that boundary to exercise start/stop/switch, duplicate starts, overlap rejection, endpoint adjacency, pending continuation, re-lock, duplicate wake/unlock notifications, and user-action races without nine-second real waits.
- Test manual historical creation, drawing through now with delayed task selection, cancellation, reverse drags, minute snapping, resize/edit conflicts, and running-entry deletion. Verify both successful mutations and preservation of existing data after rejection.
- Verify persistence by saving to temporary real local storage and reopening it. Cover clean quit, checkpoint recovery, unexpected exit during pending continuation, preferences, reusable task identity, and storage failure behavior.
- Include midnight and daylight-saving cases for duration and timestamp editing. Confirm monotonic countdown behavior independently of changes to displayed wall time where the implementation separates those clocks.
- Manually verify native menu bar and Dock behavior, actual trackpad scroll/pinch/drawing, editor focus and keyboard use, real lock/sleep transitions, non-focus-stealing continuation, dismissal during countdown, and login startup on the target Mac. Simulated lifecycle tests alone do not establish that platform integration works.
- Manually verify light/dark appearance, contrast, transparency, and motion preferences, readable task colors, accessible labels, and the behavior of the packaged app outside the development process.
- Include relevant checks in every vertical slice. Final delivery verification exercises the combined flows rather than deferring all testing or native appearance to the end.

## Out of Scope

- Calendar integration, planned future entries, reminders, and future scheduling.
- Accounts, cloud services, peer-to-peer synchronization, and Automerge integration.
- Additional task fields, projects, billing, reports, exports, and task deletion/archiving workflows.
- Automatic inactivity detection, application monitoring, or inferring the task from computer use.
- Overlapping entries, simultaneous timers, automatic trimming/replacement, and a full undo system.
- Zoom buttons, a full desktop workspace, mobile versions, support for older macOS releases, and distribution to other users.

## Further Notes

The user approved the product interview and proposed testing approach, then added native macOS and Liquid Glass as explicit requirements. The source design notes and glossary remain in the repository for context; this spec is the implementation reference.

The main platform integration risks are reliably distinguishing lock from display inactivity and presenting an automatic menu bar popover without stealing focus. Verify both on the actual Mac and report any limitation before claiming those behaviors complete.

## Task tags

The [inline task tags task](../tasks/20261021-125643/TASK.md) defines plain-text `:tag` input for task creation and editing. Tags belong to reusable tasks and apply to all their past and future entries, without entry-level overrides. Starting or creating an entry adds explicitly typed tags to existing task tags; editing replaces the complete tag list on Return. Tag changes preserve entry identity, timestamps, and running state. Task reassignment in the editor loads the destination's name and tags first and commits on Return.

Recognize whitespace-separated words beginning with `:` and not ending with `:` anywhere in the input. Preserve ordinary colons and emoji-style `:peka:` words; remove tag tokens and clean task-name spacing. Use Unicode-aware case-insensitive matching, lowercase display, and deduplication, including non-Latin scripts. Older tasks load without tags; do not reinterpret saved names automatically. Unused tags disappear when no task references them.

Offer native keyboard-accessible autocomplete from saved task tags with no initial selection. Arrow keys select; Tab or Return inserts the selected tag as plain text plus a space. Return without a selection submits the input. Escape dismisses autocomplete before canceling the draft. Support completion at the caret without replacing surrounding text. Completed tags filter task suggestions by all specified tags, ordinary text filters names, and the configured Task order still applies. Tag-only search is allowed, but saving requires a name or selected task. Display tags beside suggestion names and in timeline tooltips; keep timeline labels and the running header focused on the name. Projects, statistics, and a dedicated tag-management page remain outside this change.
